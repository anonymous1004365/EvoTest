# Virtual Invocation of Interface Object Methods

## Instructions

- WHEN the TG encounters bytecode generation logic that creates method invocation instructions (e.g., `MethodInvocation`, `InvokeDynamic`, or similar), especially for methods inherited from `java.lang.Object` (e.g., `hashCode`, `toString`, `equals`, `getClass`, `notify`, `wait`) invoked on **interface types**
  - THEN it should verify that the generated bytecode correctly uses `invokevirtual` (not `invokespecial`) for such invocations.
  - Specifically, when the owner type is an interface and the method is defined by `java.lang.Object`, the invocation must be dispatched virtually on the interface type, not statically (invokespecial) on the interface itself.
  - The test should create a scenario where an interface declares no method but inherits an Object method, and the bytecode generator creates an invocation for it — expecting `Opcode.INVOKEVIRTUAL` or similar virtual dispatch, NOT `Opcode.INVOKESPECIAL` or `Opcode.INVOKEINTERFACE`.

- WHEN the TG writes a test for this pattern
  - THEN it should use a concrete interface type (e.g., a custom interface like `Runnable`, `Callable`, or a test-defined `Foo` interface) and attempt to invoke an Object method on it via the bytecode generation API.
  - It should assert that the generated `MethodInvocation` or equivalent instruction is virtual (invokevirtual), not static/special (invokespecial).
  - Example: For an interface `SampleInterface` with no methods, invoking `hashCode` on `SampleInterface` should yield a virtual invocation, not a special one.

- Common pitfalls:
  - Testing only concrete class types (e.g., `Object`, `String`, `FooClass`) — the bug specifically manifests with **interface** owner types.
  - Testing only interface-declared methods — the bug is about **Object-inherited** methods invoked on interface owners.
  - Assuming invokespecial or invokeinterface is always correct — for Object methods on interfaces, invokevirtual is required by the JVM specification.

### Example (Correct)

```java
// Given an interface type that has no declared methods
TypeDescription interfaceType = new TypeDescription.ForGenericType(
    new TypeDescription.Latent("com.example.SampleInterface", 
        TypeDescription.Generic.Visitor.NoOp.INSTANCE,
        new TypeDescription.ForLoadedType(Object.class),
        new TypeList.Empty(),
        new AnnotationList.Empty()
    ) {
        @Override
        public boolean isInterface() { return true; }
    }
);

// When invoking an Object method on this interface
MethodDescription hashCodeMethod = new MethodDescription.ForLoadedMethod(
    Object.class.getDeclaredMethod("hashCode")
);
MethodInvocation invocation = MethodInvocation.invoke(hashCodeMethod, interfaceType);

// Then the invocation should be virtual, not special
assertThat(invocation.isVirtual(), is(true));
// And the opcode should be INVOKEVIRTUAL, not INVOKESPECIAL
assertThat(invocation.getOpcode(), is(Opcodes.INVOKEVIRTUAL));
```

### Example (Incorrect)

```java
// BUGGY: Testing with a concrete class instead of an interface
MethodInvocation invocation = MethodInvocation.invoke(
    Object.class.getMethod("hashCode"),
    TypeDescription.ForLoadedType.of(Object.class)
);
// This test would pass even on buggy code because the bug only manifests for interface owners
