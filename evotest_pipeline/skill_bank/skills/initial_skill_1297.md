# Conflict Detection with Clock Skew

## Instructions

- WHEN the TG encounters a `DocumentNodeStore` or similar distributed document store that supports `commit` operations across multiple cluster node instances, AND the system uses revision-based conflict detection (e.g., `Revision`, `RevisionVector`) where timestamps from different nodes are compared
- THEN the TG MUST write a test that:
  1. Creates TWO `DocumentNodeStore` instances (simulating two cluster nodes, e.g., `ns1` and `ns2`) with intentionally **different internal clock times** (clock skew). Use `Clock.offset` or `Clock.frozen` to advance one node's clock (e.g., +1 hour) relative to the other.
  2. On the node with the **earlier** clock time (`ns1`), perform a commit operation (e.g., a `merge` on a `Root` that adds a property like `"p"` to a node).
  3. On the node with the **later** clock time (`ns2`), attempt the **same conflicting commit** (e.g., same root, same property path).
  4. **Assert that the second commit throws a `CommitFailedException`** (specifically a commit conflict), because the revision generated by `ns2` has an earlier timestamp than `ns1`'s revision (due to the clock skew), and the conflict detection logic must reject it.
  5. Additionally, verify that the **first commit actually succeeded** (no exception thrown).

- Common pitfalls to avoid:
  - Testing only with synchronized clocks — clock skew is a realistic distributed systems scenario and must be explicitly tested.
  - Forgetting to use `Clock` (e.g., `org.apache.jackrabbit.oak.commons.concurrent.Clock`) to control time for each cluster node independently.
  - Writing a test that simply expects any exception — must specifically expect `CommitFailedException` to verify conflict detection, not some other error (e.g., `DocumentStoreException`).
  - Not checking that the non-skewed node's commit succeeds, so the test might pass even if the whole commit mechanism is broken.

- Example (correct):
  ```java
  // Arrange two cluster nodes with clock skew
  Clock clock1 = new Clock(this.clock);
  Clock clock2 = Clock.offset(clock1, Duration.ofHours(1));

  DocumentNodeStore ns1 = builder().clock(clock1).setAsyncDelay(0).build();
  DocumentNodeStore ns2 = builder().clock(clock2).setAsyncDelay(0).build();

  // Act: commit on ns1 (earlier clock)
  Root r1 = ns1.getRoot();
  r1.getChild("node1").setProperty("p", "v1");
  r1.commit();

  // Act & Assert: same conflicting commit on ns2 must fail
  Root r2 = ns2.getRoot();
  r2.getChild("node1").setProperty("p", "v2");
  assertThrows(CommitFailedException.class, () -> r2.commit());
  ```

- Example (incorrect — missing clock skew):
  ```java
  // BAD: uses same clock, no clock skew
  DocumentNodeStore ns1 = builder().clock(clock).setAsyncDelay(0).build();
  DocumentNodeStore ns2 = builder().clock(clock).setAsyncDelay(0).build();

  Root r1 = ns1.getRoot();
  r1.getChild("node1").setProperty("p", "v1");
  r1.commit();

  Root r2 = ns2.getRoot();
  r2.getChild("node1").setProperty("p", "v2");
  r2.commit(); // This may succeed without clock skew, masking the bug
  // No assertion, no expected exception
  ```
